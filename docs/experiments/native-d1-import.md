## 2. Viewer implementation

- \`site/native-import.mjs\`: bounded, **browser-only read-only** \`FileList\` importer; validates strict ten-field run envelope, per-run event sequence starting at zero, six event fields, source-native sorted pair-array, material references and SHA-256, spans, model call identity/counters and basic Procedure invocation lineage. Returns local presentation with explicit \`sourceLocator\` and \`ca-agent-demo:run:seq\` IDs. **No raw material bodies are rendered by default.**
- \`site/app.tsx\`: directory selector (Chromium \`webkitdirectory\`), error display, local Run selection and source Inspector; header distinguishes \`LOCAL NATIVE · NOT OWNER VERIFIED\` from \`SYNTHETIC DATA\`. **One selected Run directory at a time**; no ZIP, upload or API call.
- \`site/projection.mjs\`: accepted presentation sources are explicit \`SYNTHETIC\` or \`NATIVE_LOCAL\`; pre-existing synthetic fixture validation stays separate.
- \`site/console-parity.mjs\`: Model Request/Response folding requires exact owner \`model_stage/call_index/model_call_id\` correlation; no guessed cross-owner Tool links. Deterministic native Run produces no Model-only cards. Runtime stage is a display lane only, not a Runtime Owner claim.

**Important precision:** Native \`TraceEvent\` has no per-event \`occurredAt\`. This importer does not fabricate timestamps, Span durations, cross-owner sequences, external dispositions or tool causality. Timed native \`TraceSpan\` records are validated as metadata but are **not yet** losslessly projected into all Viewer tabs.

### Import instructions

Open Viewer → left sidebar **Import TraceStore v2 folder** → select exactly one \`.runs/<run_id>/\` directory generated by the Owner. It must contain:

~~~text
<run_id>/
  run.json
  trace.jsonl
  materials/
    <digest>.json     # zero or more
~~~

The browser reads the directory **locally**. It does not run \`TraceStore.load_run\`, requery remote providers or upload files. A successful local import proves only the implemented structure/content checks, **not** full owner validation or business Evidence closure. To establish full source validity, run the Owner's \`TraceStore.load_run\` in an authorized environment as done for the synthetic golden fixtures.

### Current deliberate limits

- Format \`trace_format_version=2\` only; no ZIP, streaming, OTLP import or multi-run folder.
- 120 files, 20 MiB total, 8 MiB per file, 30,000 events, 5,000 spans and capped text/depth. These are prototype safety limits, **not** official Owner limits.
- Material verifier currently requires the Owner Writer's exact compact canonical JSON bytes plus LF and checks \`SHA-256(canonical bytes without LF)\`. It may reject valid Loader-compatible noncanonical JSON or certain Python/JS float serialization cases with \`CANONICAL_UNSUPPORTED\`; it never silently claims parity.
- Some Owner validations (request-assembly digests, full Model timing Span correlation, fine-grained Procedure lineage beyond the implemented checks, unsafe nested unusual inputs) still require the upstream Python \`load_run\`. This is why the Viewer says **NOT OWNER VERIFIED** for arbitrary local imports.
- \`FileList\` cannot prove that an empty \`materials/\` directory existed when no material files are returned. Empty material listing and zero refs are supported with the caveat.
- No real 5GC/CreatedSession/DSH/Console Run is used; the two generated sources are expressly **synthetic**. No “all D1 tests passed” claim for real production materials.
